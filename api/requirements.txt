# Dependencies for the Vercel Python function. This is the ONLY requirements
# file Vercel sees, and it lives here on purpose.
#
# There used to be a copy at the repo root as well. That is what broke the
# deploy: a root requirements.txt makes Vercel classify the whole project as a
# "backend framework project" — its own build log says so — and it then routes
# every request through a backend adapter instead of serving the static build.
# The symptoms were `/` crashing a function instead of returning index.html,
# and even a pure-standard-library function failing to invoke.
#
# Keep dependency files OUT of the repo root. api/ for the function,
# backend/ for running the API locally.
#
# Deliberately NOT backend/requirements.txt. The Google Drive image sync pulls
# in google-api-python-client and its dependency tree, which is tens of
# megabytes against a 250 MB function bundle — and it is useless here anyway,
# because a serverless container has nowhere durable to put the images it
# downloads. Those imports are all inside functions in backend/images.py, so
# leaving the packages out costs nothing until someone calls the Drive endpoint,
# which then reports that Drive is unavailable.
#
# Run the backend locally from backend/requirements.txt, which has the full set.

pydantic==2.12.5
httpx==0.28.1
